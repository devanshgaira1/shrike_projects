

# 5-Channel FPGA Data Logger

**Difficulty:** Intermediate
**Uses MCU:** Yes (ESP32-S3)
**External Hardware:** Shrike FPGA Board, ESP32-S3, Arduino Mega (for testing), Breadboard, Jumper Wires.

## Overview

The `fpga_data_logger` project implements a 5-channel data logging system using the Shrike FPGA as the primary data acquisition source. It demonstrates how to utilize FPGA hardware to stream parallel data channels over UART, which is then captured and processed by an ESP32-S3. This setup is ideal for monitoring multiple signal sources simultaneously and streaming them to a computer via Serial.

## Hardware Setup

* **Soldering:** Ensure that all header pins are soldered onto your Shrike FPGA board to ensure reliable electrical connections.
* **Testing with Arduino Mega:** Before integrating with the FPGA, use an Arduino Mega to verify your pin mapping and UART logic using the `mega_sender_5ch.ino` test sketch. This ensures your wiring to the ESP32-S3 is correct and that the serial communication protocol is stable before finalizing the FPGA bitstream.


* **Final Wiring:** Connect the FPGA signal output (`FPGA_RX_PIN`) to **GPIO 4** on the ESP32-S3. Ensure a **common GND** is established between the FPGA, the ESP32-S3, and any power sources to prevent signal noise.



## Quick Start (Pre-Built Bitstream)

1. Connect your Shrike board via USB.


2. Upload `bitstream/fpga5ch.bin` using ShrikeFlash.


3. Connect the FPGA signal pin to **GPIO 4** on your ESP32-S3.


4. Upload the `fpga_data_logger.ino` to your ESP32-S3.


5. Open the Serial Monitor at **115200 baud**.


6. **Expected result:** You should see a continuous stream of 5-channel data logs in CSV format, including a timestamp for each entry.



## Build From Source

### Firmware (Arduino)

1. Open `firmware/arduino-ide/fpga_data_logger.ino` in Arduino IDE.


2. Select your ESP32-S3 board.
3. Upload the sketch.



## How It Works

The FPGA acts as a multi-channel UART transmitter. The ESP32-S3 captures this data and aggregates it into a single, timestamped CSV format, which allows for easy debugging and data analysis via the Serial Monitor.

## Expected Output

The system outputs a CSV-formatted stream containing the following columns: `millis,ch0_up,ch1_zero,ch2_bin4,ch3_hex,ch4_up2`.

* **millis**: System time in milliseconds since the ESP32 booted.


* **ch0_up**: An up-counter (starts at 0).


* **ch1_zero**: A constant zero value.


* **ch2_bin4**: A 4-bit binary representation of a counter cycling 0–15.


* **ch3_hex**: A counter displayed in hexadecimal format.


* **ch4_up2**: A second independent up-counter that increments by 2.

## Troubleshooting

If you encounter unexpected data or connectivity issues:

* **Use the Testing Sketch:** If the FPGA data is inconsistent, revert to the `mega_sender_5ch.ino` test sketch. If the ESP32 receives data correctly from the Mega, the issue is likely within the FPGA clock division or synthesis settings.


* **Check Soldering:** Verify that all header pins on the Shrike board are firmly soldered.


* **Check Baud Rates:** Ensure the ESP32 baud configuration (`9600` in the sketch) matches the specific clock-divided rates generated by the FPGA logic.


* **Common Ground:** Double-check that all boards share a common ground wire.


* **Serial Monitor:** If you see garbled text, ensure your Serial Monitor is explicitly set to 115200 baud.
